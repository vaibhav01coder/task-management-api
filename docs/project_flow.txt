3. API ENDPOINTS
--------------------------------------------------------------------------------

  METHOD   ENDPOINT                  DESCRIPTION
  -------  ------------------------  -------------------------------------------
  POST     /tasks                    Create a new task
  GET      /tasks                    List tasks (paginate / filter / search)
  GET      /tasks/summary            Aggregate counts by status and priority
  GET      /tasks/<id>               Get a single task by ID
  PUT      /tasks/<id>               Update task fields
  DELETE   /tasks/<id>               Delete a task
  PATCH    /tasks/<id>/complete      Mark task as complete

4. SEARCH & SUMMARY (KAN-4 FEATURE)
--------------------------------------------------------------------------------

  GET /tasks?search=<keyword>
  ┌─────────────────────────────────────────────────────────────────────┐
  │  1. Extract ?search= from query string                              │
  │  2. validate_search_param()                                         │
  │       blank string      → 400 {"message": "search term must not..."}│
  │       whitespace only   → 400                                       │
  │       length > 200      → 400                                       │
  │       valid             → strip whitespace, pass on                 │
  │  3. build_search_query()                                            │
  │       SQL: WHERE (title ILIKE '%kw%' OR description ILIKE '%kw%')  │
  │            AND status = ?    (if ?status= provided)                 │
  │            AND priority = ?  (if ?priority= provided)              │
  │  4. Paginate → return {tasks, total, page, limit, pages}           │
  └─────────────────────────────────────────────────────────────────────┘

  GET /tasks/summary
  ┌─────────────────────────────────────────────────────────────────────┐
  │  1. Set REPEATABLE READ isolation (PostgreSQL)                      │
  │     SQLite: try/except fallback, log debug warning                 │
  │  2. COUNT(id)                          → total                      │
  │  3. GROUP BY status  COUNT(id)         → by_status  {k: n, ...}    │
  │  4. GROUP BY priority COUNT(id)        → by_priority {k: n, ...}   │
  │  5. Return {total, by_status, by_priority}                         │
  │                                                                     │
  │  Example response:                                                  │
  │  {                                                                  │
  │    "total": 10,                                                     │
  │    "by_status":   {"pending": 5, "in_progress": 3, "complete": 2}  │
  │    "by_priority": {"high": 4, "medium": 4, "low": 2}               │
  │  }                                                                  │
  └─────────────────────────────────────────────────────────────────────┘
